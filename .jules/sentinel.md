## 2025-03-06 - [Hardcoded Admin Credentials]
**Vulnerability:** Found hardcoded super admin credentials in `src/contexts/AdminContext.tsx`. The credentials (`SUPER_ADMIN_USER = "muhammadsolih"` and `SUPER_ADMIN_PASS = "muhammadsolih2234"`) are explicitly stored in the client-side code.
**Learning:** In a pure frontend application, any hardcoded credentials can be easily read by anyone inspecting the code or the bundled JavaScript files. This grants unauthorized full admin access to the application, bypassing all intended security controls.
**Prevention:** Never hardcode credentials or secrets in the client-side code. Use environment variables (e.g., `import.meta.env.VITE_SUPER_ADMIN_USER`) during the build process, or implement a proper backend service for authentication where secrets remain on the server.

## 2025-03-06 - [Authentication Bypass via Empty Passwords]
**Vulnerability:** The authentication system allowed users to bypass authentication if their password was an empty string `""` or `undefined`. A ternary operation `const hashedPassword = password ? await hashPassword(password) : undefined;` mapped an empty string to `undefined`, which was then evaluated against a stored `undefined` (common for Google Auth users), causing the check `existingUser.password !== hashedPassword` (`undefined !== undefined`) to evaluate to `false`, thus allowing login.
**Learning:** Checking for equality when both the input and the target stored value are `undefined` creates a bypass vector. Conditional hashing that falls back to `undefined` introduces high risk if user state inherently relies on falsy values to represent a lack of a password.
**Prevention:** Always enforce strong typing and assert that passwords are valid, non-empty strings (`!password` check) before proceeding with hashing and verification. Ensure Google or external auth users cannot be logged into manually via standard username/password forms.
