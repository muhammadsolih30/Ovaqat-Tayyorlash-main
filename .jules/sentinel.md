## 2025-03-06 - [Hardcoded Admin Credentials]
**Vulnerability:** Found hardcoded super admin credentials in `src/contexts/AdminContext.tsx`. The credentials (`SUPER_ADMIN_USER = "muhammadsolih"` and `SUPER_ADMIN_PASS = "muhammadsolih2234"`) are explicitly stored in the client-side code.
**Learning:** In a pure frontend application, any hardcoded credentials can be easily read by anyone inspecting the code or the bundled JavaScript files. This grants unauthorized full admin access to the application, bypassing all intended security controls.
**Prevention:** Never hardcode credentials or secrets in the client-side code. Use environment variables (e.g., `import.meta.env.VITE_SUPER_ADMIN_USER`) during the build process, or implement a proper backend service for authentication where secrets remain on the server.
## 2025-03-06 - [Authentication Bypass via Missing Password Check]
**Vulnerability:** Found a critical authentication bypass in `src/contexts/AuthContext.tsx` where the check `existingUser.password !== password` was bypassing normal checks when `password` is omitted or passed as `undefined`. This would inadvertently log the user in if their stored password was `undefined` (e.g. Google-registered users). Also, the login function was leaking information by verifying account existence separate from incorrect passwords (Account Enumeration).
**Learning:** In dynamically-typed environments or when interacting with properties that can be `undefined`, simple inequality comparisons against inputs can lead to type coercion bypasses. Strict validation of all authentication inputs must be done.
**Prevention:** Ensure explicit falsy checks or combined generic checks (e.g., `!existingUser || existingUser.password === undefined || existingUser.password !== password`) are used for password comparisons, and consolidate error messages to prevent enumeration.
