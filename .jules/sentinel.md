## 2025-03-06 - [Hardcoded Admin Credentials]
**Vulnerability:** Found hardcoded super admin credentials in `src/contexts/AdminContext.tsx`. The credentials (`SUPER_ADMIN_USER = "muhammadsolih"` and `SUPER_ADMIN_PASS = "muhammadsolih2234"`) are explicitly stored in the client-side code.
**Learning:** In a pure frontend application, any hardcoded credentials can be easily read by anyone inspecting the code or the bundled JavaScript files. This grants unauthorized full admin access to the application, bypassing all intended security controls.
**Prevention:** Never hardcode credentials or secrets in the client-side code. Use environment variables (e.g., `import.meta.env.VITE_SUPER_ADMIN_USER`) during the build process, or implement a proper backend service for authentication where secrets remain on the server.

## 2023-10-25 - [Authentication Bypass and Account Enumeration]
**Vulnerability:** The client-side mocked `login` function in `src/contexts/AuthContext.tsx` explicitly detailed whether an account existed ("Bunday foydalanuvchi topilmadi") or if the password was wrong ("Parol xato"), enabling account enumeration. Additionally, Google OAuth users inherently had an `undefined` password in their state. The traditional login process lacked strict checking against this, allowing a user who logged in via Google to have their account breached if someone attempted traditional login without providing a password (though input fields mitigate this, bypassing frontend validation would allow it).
**Learning:** Client-side authentication logic must be treated as rigorously as server-side logic in mock systems. Distinct error messages for non-existent users and incorrect passwords leak account existence. Strict type checking and explicit validation for `undefined` passwords are required when mixing OAuth and traditional auth flows in state.
**Prevention:** Use generic error messages (e.g., "Email yoki parol xato.") for all login failures. Always implement strict falsy checks or explicit checks for missing/undefined passwords in traditional authentication paths to prevent unintentional bypasses when sharing state with OAuth-style signups.
