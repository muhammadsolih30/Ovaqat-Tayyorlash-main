## 2025-03-06 - [Hardcoded Admin Credentials]
**Vulnerability:** Found hardcoded super admin credentials in `src/contexts/AdminContext.tsx`. The credentials (`SUPER_ADMIN_USER = "muhammadsolih"` and `SUPER_ADMIN_PASS = "muhammadsolih2234"`) are explicitly stored in the client-side code.
**Learning:** In a pure frontend application, any hardcoded credentials can be easily read by anyone inspecting the code or the bundled JavaScript files. This grants unauthorized full admin access to the application, bypassing all intended security controls.
**Prevention:** Never hardcode credentials or secrets in the client-side code. Use environment variables (e.g., `import.meta.env.VITE_SUPER_ADMIN_USER`) during the build process, or implement a proper backend service for authentication where secrets remain on the server.
## 2025-03-08 - Fixed plaintext user password storage
**Vulnerability:** User passwords in mocked local authentication were stored in plaintext within localStorage (`taomuz_users`), creating a significant risk of exposure to local attackers or XSS payload theft.
**Learning:** Even client-side mock authentication layers must simulate secure handling principles. Implementing Web Crypto API's PBKDF2 with a random salt establishes correct architectural patterns for later server integration, preventing credential exposure. Backward compatibility can be handled safely without regressing security on new accounts.
**Prevention:** Use `crypto.subtle.deriveBits` with PBKDF2/SHA-256 (minimum 100,000 iterations) alongside unique per-user salts (`crypto.randomUUID()`) when validating and storing client-managed mocked credentials. Do not use localstorage to hold plaintext user passwords.
